Hareyeng is in production as a minibus taxi route guide for people who need a clearer way to understand local travel. The current build maps taxi ranks and the routes connecting them.

## Local knowledge, made visible

Taxi routes are often explained through knowledge shared between passengers and drivers. Hareyeng is designed to give that information a useful place on the map, then build toward community contributions.

The longer-term guide includes route segments that can be hailed along the way, fare notes, hand signs, and reports about route conditions. These community features are planned work; the current implementation is focused on rank and route data.

## From map data to an API

The first version used a local JSON file to prove the map flow. The next step moved rank and route records into MongoDB Atlas and exposed them through an Express API.

```text
React + TypeScript + Mapbox GL JS
                 |
            REST / GeoJSON
                 |
        Node.js + Express API
                 |
       MongoDB Atlas + Mongoose
```

The frontend requests GeoJSON from the API and passes it to Mapbox as map sources and layers. That keeps map rendering separate from the stored rank and route records.

## Geospatial data choices

Rank locations use GeoJSON points, while routes use GeoJSON line strings. MongoDB 2dsphere indexes support proximity lookups as the dataset grows.

```ts
const RankSchema = new Schema({
  name: { type: String, required: true },
  location: {
    type: { type: String, enum: ["Point"], required: true },
    coordinates: { type: [Number], required: true }, // [longitude, latitude]
  },
});

RankSchema.index({ location: "2dsphere" });
```

Coordinates follow GeoJSON order: longitude first, latitude second. A repeatable seed script makes it possible to rebuild the local dataset without entering records by hand.

## Current build and next steps

Rank and route models are in place, and the API exposes `GET /api/ranks` and `GET /api/routes`. The `Report` model is still a stub. A practical check for the API-backed flow is to rename a rank in the database and confirm that the updated name appears after refreshing the map.

| Stage | Planned focus |
| --- | --- |
| 3 | Hailable route segments and community reports |
| 4 | Accounts, voting, confidence scores, and stale-report handling |
| 5 | Researched local data, mobile layout, and map filters |
| 6 | Deployment and a public mobile-friendly link |

The project is intentionally scoped to one town for now. It does not include live vehicle tracking, queue estimates, or passenger counts.

## Technology

React, TypeScript, Mapbox GL JS, Node.js, Express, Mongoose, and MongoDB Atlas form the current stack. JWT authentication and deployment are part of later project stages.
